# RMD-1802 source-analysis cancellation review — 2026-10-14

Independent production-path review found that `SourceAnalysisUseCase.analyzeBlocking` caught every `Exception` from `AppSourceAnalysisGateway.analyze`, including `java.util.concurrent.CancellationException`. A cancelled resolver call could consequently be classified as a retryable `SOURCE_ANALYSIS_UNAVAILABLE` provider failure instead of preserving cancellation. This violates coroutine cancellation semantics and risks publishing a misleading failure when an analysis was deliberately cancelled.

The production boundary now rethrows `CancellationException` before its generic, safely redacted exception mapper. It intentionally does **not** call `cancelActive()` from that catch: another request may have superseded the cancelled ticket concurrently, and blindly clearing the active ticket would invalidate the newer request. Existing UI disposal/supersession logic retains responsibility for invalidation.

Deterministic host-JVM regression `SourceAnalysisUseCaseTest.gatewayCancellationPropagatesRatherThanBecomingRetryableSourceFailure` proves the cancellation exception reaches the caller, rather than being mapped to an ordinary provider error; the existing thrown-provider-error test still proves safe fallback for genuine runtime exceptions. This is a focused independent-review correction, **not** a claim of complete RMD-1802 or final engineering closeout. Record passing exact-head CI and Android qualification before checking RMD-1802/RMD-1803/RMD-1805 or the global proof rules. External service-policy/legal approval remains separate.
